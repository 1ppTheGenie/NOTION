🔄 Application Flow Diagram

Complete process flow from start to finish with decision points

Phase 1: Entry & Property Lookup
🚀 START → 1️⃣ Enter Address → 🌐 Geocode → Valid?
↳ NO → ❌ "Address not found" → Back to Screen 1
↳ YES → 🗄️ Query Attom → Data? → ✓ Pre-fill OR ⚠️ Manual
Phase 2: Listing Type & Details
2️⃣ Select Status → 3️⃣ Property Details → Valid?
↳ NO → ❌ Highlight invalid fields
↳ YES → Continue
Phase 3: Photos & Description
4️⃣ Upload Photos → ☁️ S3 Upload → ≥1?
↳ NO → ❌ "At least 1 photo required"
↳ YES → 5️⃣ Description → Use AI? → 🤖 Paisley OR ✍️ Manual
Phase 4: Agent & Area
6️⃣ Select Agent → Role?
↳ Agent → Load Own Profile
↳ Title Rep → Query Partners
↳ Admin → Search All
7️⃣ Select Area → Continue
Phase 5: Publish
8️⃣ Review → Publish → 🔢 PLS# → INSERT Listing → INSERT Photos
→ INSERT Ownership → Success?
↳ ERROR → ❌ Rollback + Show Error
↳ SUCCESS → 🎨 GenieCloud → 9️⃣ Success! → ✅ END

❓ "What If" Decision Matrix

How the system handles every edge case and error scenario

Scenario What Happens User Action
Address not found in geocoding Error shown, stays on Screen 1 Re-enter address or use manual coordinates
No Attom data for property Warning shown, proceed with empty form Enter all fields manually
Photo upload fails Red X on failed photo, retry button Click retry or remove and re-upload
No photos uploaded Cannot proceed, error message Must upload at least 1 photo
Paisley AI times out Show timeout message, enable manual entry Type description manually or retry
Title Rep has no partner agents Show empty state with "Invite Agent" button Invite agent first, or use Admin flow
Database insert fails Transaction rolled back, error shown Retry, data preserved on form
GenieCloud render fails Listing created, but assets pending Assets will retry automatically via queue
User refreshes mid-wizard Session state preserved (localStorage backup) Continue from where they left off
User closes browser mid-wizard Draft saved if past Screen 3 Resume from drafts on next login

  • 1. usp_GetNextPlsNumber → PLS#

  • 4. INSERT PlsListingOwnership
  • 5. Trigger GenieCloud render

❌ If Publish Fails

  • Roll back entire transaction
  • Show error message
  • Keep data intact for retry

🗄️ Database Schema Summary

All tables and fields touched by the PLS creation flow

Database Table Key Fields Notes
MlsListing Listing MlsNumber, Address, Price, Beds, Baths, Sqft, Remarks MlsId=999 for all PLS listings
MlsListing Photo ListingId, PhotoUrl, SortOrder S3 URLs stored here
MlsListing StatusType StatusTypeId, Name 6=Private, 14=Coming Soon
FarmGenie PlsListingOwnership PlsNumber, UserId, AgentUserId, CreatedDate NEW TABLE
FarmGenie PlsNumberSequence Year, CurrentNumber NEW TABLE
FarmGenie Area AreaId, Name, City, State For market stats
FarmGenie UserMarketingProfile UserId, DisplayName, Email, Phone Agent info
TitleData ViewAssessor_v3 Address, Beds, Baths, Sqft, YearBuilt READ ONLY - Attom data

🔢 Stored Procedure: usp_GetNextPlsNumber

  • Generates unique PLS numbers in format: PLS-2025-00001
  • Thread-safe with transaction locking
  • Resets counter each year
